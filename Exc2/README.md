# Мотивация

Добавление мониторинга в систему повышает наблюдаемость системы и позволяет вовремя предпринять шаги для обеспечения стабильности и производительности бизнеса.  
    
Внедрение мониторинга позволит:  
1. Быстрее обнаруживать проблемы с производительностью, что позволит оперативно     реагировать на них.  
2. Понять как пользователи взаимодействуют с системой, что поможет улучшить пользовательский опыт.  
3. Своевременно выявлять и устранять проблемы в работе системы, что поможет избежать негативных отзывов и сохранить контракты с партнерами.
4. Обосновать необходимость выделения ресурсов на улучшение инфраструктуры.

# Выбор подхода к мониторингу

Для мониторинга системы рекомендуется использовать подход «Четыре золотых сигнала».  
Четыре золотых сигнала — это ключевые метрики для мониторинга состояния и производительности информационных систем.

1. Задержка (Latency). Время, необходимое для обработки запроса. Важно различать задержку успешных и неудачных запросов.  
2. Трафик (Traffic). Количество запросов к системе. Для веб-службы это обычно количество HTTP-запросов в секунду, разделённые по характеру запросов (например, статический или динамический контент). Для системы потоковой передачи звука это измерение может быть сконцентрировано на скорости ввода-вывода сети или количестве одновременных сеансах.  
3. Ошибки (Errors). Частота неудачных запросов, которые определены явно (например, HTTP 500), неявно (например, HTTP 200, но в сочетании с неправильным контентом) или условиями системы.  
4. Насыщенность (Saturation). Насколько интенсивно используется сервис. Это мера системного мониторинга, выявляющая ресурсы, которые наиболее ограничены (например, в системе с ограниченной памятью — память, в системе с ограничениями ввода/вывода — количество вводов-выводов).

Этот подход позволит получить полное представление о состоянии системы и выявить потенциальные проблемы.

# Метрики

1. Мониторинг загрузки CPU, утилизации памяти (Memory Utilisation) и свободного места на диске для всех ВМ

2. Мониторинг RPS (Number of requests) в API (Shop API, CRM API, MES API)  

3. Мониторинг Response time (latency) в API (Shop API, CRM API, MES API) 

4. Мониторинг ошибок (500) в API (Shop API, CRM API, MES API) 

5. Мониторинг RabbitMQ
- `Number of dead-letter-exchange letters`
- `Number of message in flight`
- `Number of messages in queues`

6. Мониторинг заполненности S3 хранилища
- `Size of S3 storage`

7. Мониторинг количества активных сессий
- `Number of simultanious`

8. Мониторинг БД (Shop db, MES db)
- `Size of db`
- `Number of connections`

Данные метрики помогут создать полное представление о состоянии системы и выявить потенциальные проблемы.

# План действий

1. Определение требований и выбор инструментов мониторинга:
   Назначить встречу с заинтересованными сторонами и согласовать список метрик, которые будут отслеживаться. Например можно остановиться на Prometheus.

2. Развернуть систему мониторинга
   
3. Настроить сбор метрик
   - Внедрить агенты мониторинга (Prometheus Exporters), для сбора данных загруженности ВМ.
   - Адаптировать сервисы для сбора и предоставления метрик RPS, Response time, Http response type, ... 

4. Установить и настроить систему визуализации  
   Использовать инструмент для визуализации метрик и создания дашбордов.
   Например Grafana или Kibana

5. Определение пороговых значений и настройка уведомлений  
   - Установить предупреждения и алерты для ключевых показателей.
   - Настройка уведомлений по email и другим каналам передачи уведомлений
