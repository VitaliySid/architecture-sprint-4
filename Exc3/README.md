# Мотивация

Внедрение трассировок запросов в систему необходимо для улучшения наблюдаемости системы, а именно:  
- Улучшение диагностики проблем и выявление узких мест в процессе обработки заказов
- Анализ времени обработки заказа в каждом сервисе
- Анализ количества ошибок на каждом этапе обработки заказа

# Предлагаемое решение

Для сбора и экспорта данных о микросервисах будем использовать OpenTelemetry, он поддерживает трассировку, метрики и логи, что обеспечивает комплексный подход к мониторингу. Доставка данных трассировок будет происходить через брокер сообщений.
Для визуализации и анализа трассировок будем использовать Jaeger

# Компромиссы

Трассировки запросов могут не принести пользы в следующих случаях:
- Если система используется редко, затраты на трейсинг могут не оправдать себя
- Если системы, которые необходимо отслеживать, имеют проприетарные API, которые не поддерживают необходимые метрики
- Если внедрение трейсинга требует значительных ресурсов и времени, что может отвлечь от других приоритетных задач
- Если Внедрение трейсинга может добавить дополнительную нагрузку на систему, что может негативно сказаться на производительности

# Аспекты безопасности
      
Доступ к системе визуализации трассировок будут иметь только сотрудники с определенной ролью/ролями;  
Доступ в брокер сообщений будет так же ограничен списком учетных записей.
