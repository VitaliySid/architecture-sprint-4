# Архитектурное решение по кешированию

![](/Схемы/sequence-diagram.png)

## Мотивация

Внедрение кеширования в систему компании позволит снизить нагрузку на серверы баз данных и ускорить время загрузки страниц.

## Предлагаемое решение

Серверное кеширование, оно позволит централизованно управлять данными, снизить нагрузку на серверы и уменьшает время отклика для всех пользователей.

Особенности: требуется детальная проработка кеша в случае сложной ролевой модели и разных данных, доступных для операторов.

Предлагается использовать паттерн `Cache-Aside`.  
Использование этого паттерна позволит полностью контроллировать данные в кеше на серверной части приложения. Данный паттерн хорошо подходит для часто читаемых и редко изменяемых данных.

Что касается других паттернов:
- `Write-Through` - Паттерн больше заточен под запись в БД. Более сложная настройка кеша. Обновляется сначала кеш, потом БД и т.к. операция синхронная, клиент не получит ответа, пока база не обновится.
- `Refresh-Ahead`: Сложный в управлении и может привести к устаревшим данным. Ошибки в работе кеша приведут к неконсистентности данных и чтению из базы.


## Стратегия инвалидации кеша

Для инвалидации кеша может быть выбрано несколько стратегий:
- Стратегия: временная (Time-based)
  Обеспечивает автоматическое обновление данных через заданные интервалы времени, что упрощает управление кешем. Данная стратегия кеширования обеспечивает баланс между простотой реализации и эффективностью.
- Стратегия: по ключу
  Позволяет инвалидировать кеш для конкретных данных, что позволит производить инвалидацию кеша в случае обновления данных в БД. В нашем случае при обновлении заказа будет инвалидирован кеш, это обеспечит консистентность данных.

Сравнительный анализ стратегий:

| Стратегия             | Преимущества                                                        | Недостатки                                                 |
|-----------------------|---------------------------------------------------------------------|------------------------------------------------------------|
| Временная             | Простота реализации, автоматическое обновление                      | Возможны устаревшие данные в период между обновлениями     |
| По ключу              | Точность, обновление только измененных данных                       | Сложность отслеживания всех изменений                      |
| Программная           | Гибкость, точечное обновление                                       | Требует дополнительной логики в приложении                 |
